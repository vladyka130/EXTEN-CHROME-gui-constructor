# Конструктор GUI для Chrome-розширень

Electron-додаток, який дозволяє **імпортувати розширення, побачити його інтерфейс у живому
попередньому перегляді та перемалювати його — не чіпаючи логіку**. Файли `.js` розширення
конструктор не редагує в автоматичному режимі; автотест це окремо перевіряє.

---

## Запуск

**Linux / macOS**

```bash
./start.sh            # сам встановить залежності, якщо треба
# або
npm install && npm start
```

Потрібен Node 20+. Якщо системного Node немає, скрипт шукає портативний у `../.toolchain/node-*/bin`.

**Windows**

```bat
start.cmd
```

**Перевірка, що все працює**

```bash
node scripts/selftest.js                       # приклад examples/demo-extension
node scripts/selftest.js /шлях/до/розширення   # будь-яке розширення-папка, .zip чи .crx
```

Автотест повністю проходить кінець у кінець: імпорт → превʼю → реальний клік мишкою по елементу →
перетягування елемента й розтягування за ручку → правка стилю й тексту → запис шару у файли →
зняття шару → перевірка, що `.js` залишились байт-в-байт ідентичними.
Докази — у `.selftest/` (`result.json`, `app.png`, `preview.png`, `preview-skinned.png`,
`preview-geom.png`, `preview-arrows.png`). Автотест перевіряє й те, що рух одного елемента не
чіпає сусідів, і крок стрілок на 1 та 10 px.

## Швидкий старт

1. **Імпортувати** — обери папку розширення, `.zip` або `.crx`. Конструктор копіює вміст двічі: у
   `original/` (еталон, ніколи не змінюється) і у `working/` (з ним і працюємо).
2. **Поверхні** — зліва список усього, що бачить користувач: popup, сторінки options, сторінки
   замін (newtab тощо) і кожний `content_scripts`-набір. Обери й натисни **Дивитись**.
3. **Мережа** — якщо панель живиться з сервера, додай мок (нижче), щоб вона заповнилась даними.
4. **🎯 Вибір елемента** — увімкни і клікни по будь-якому елементу у превʼю. Конструктор сам
   підбере стабільний селектор і покаже його computed-стилі в **Інспекторі**.
5. **📐 Рух і розмір** — перетягуй елементи мишкою та тягни за квадратні ручки на кутах і сторонах,
   щоб змінити розмір; стрілки дають крок 1 px (Shift — 10 px). Правка зʼявляється в інспекторі
   одразу по відпусканні миші.
6. Міняй кольори, шрифти, відступи, заокруглення, розмір, позицію, текст; став галочку
   **приховати елемент**. Все застосовується миттєво, без перезапуску.
7. **Знімок** — фіксує стан. **Застосувати до розширення** — записує оформлення у файли.
8. **Експорт** — вивантажує готову папку (+ `.zip`) у `…-gui`, яку можна завантажити через
   `chrome://extensions → Режим розробника → «Виділена папка»`.

## Розстановка мишкою (📐 Рух і розмір)

Режим на панелі превʼю. Наведення підсвічує елемент, як у devtools:

| Дія | Результат у правці |
| --- | --- |
| тягнути елемент | `position` + `left`/`top` на величину зміщення |
| тягнути за ручку (8 штуки: кути й сторони) | `box-sizing: border-box` + `width`/`height`; ручка зліва/зверху ще й зсуває `left`/`top` |
| `←` `→` `↑` `↓` | крок рівно на 1 px від поточного місця (елемент «заблокований» наведеним мишкою) |
| `Shift` + стрілка | крок 10 px — швидко відвести елемент далеко |
| клік без руху | те саме, що «Вибір елемента»: відкриває елемент в інспекторі |
| `Tab` | перейти до батьківського елемента (щоб взяти всю панель, а не її підрядок) |
| `Shift` під час руху | блокування по одній вісі; під час розтягування кута — збереження пропорцій |
| `Esc` | вийти з режиму |

Стрілки працюють у режимі геометрії: наведи мишку на елемент (підсвітка + ручки) і тисни їх —
зміщення акумуляється по пікселю, правка записується після короткої паузи в 140 мс.

Під час перетягування елемент рухається на очах (інлайн-стилі), а по відпусканні миші значення
перетворюються на звичайну правку скіна й застосовуються через CSS — картинка не «стрибає».
Якщо `min/max-width` чи флекс-розподіл у контейнері розширення не дають розтягнути елемент,
конструктор знімає ці обмеження (`min-width: 0`, `max-width: none`, `flex-grow/shrink: 0`,
`flex-basis: auto`) і записує фактичний розмір. Числа потім можна дошліфувати вручну в
інспекторі (групи «Розмір панелі/елемента» та «Позиція»).

## Два режими редагування

### 1. Скін-шар (безпечний, типовий)

Правки зберігаються як дані, а не як переписаний код розширення. Після «Застосувати до
розширення» у `working/` з'являється:

```
gui-skin/
  skin.css          ← правила з !important, обмежені :root[data-gui-scope="…"]
  skin-data.json    ← операци: які селектори, що міняти, який текст
  skin-runtime.js   ← застосовувач: текст, класи, атрибути, приховування, переміщення вузлів
```

і `manifest.json` доповнюється ще одним `content_scripts`-записом (`run_at: document_start`,
`all_frames: true`) + `web_accessible_resources` для `skin-data.json`. Для сторінок (popup/options)
у HTML вставляються блоки між маркерами `<!-- gui-skin:start -->` / `<!-- gui-skin:end -->`.

Кнопка **Зняти скін-шар з файлів** прибирає усе: файл-оболонки, запис у маніфесті, вставки в HTML.
Стан, зафіксований у `skin.json`, лишається, тож оформлення можна застосувати повторно.

### 2. Сирі правки (вкладка «Файли»)

Текстовий редактор файлів інтерфейсу: HTML, CSS, JSON маніфесту. Перед кожним збереженням
автоматично створюється версія в історії (до 25 на файл), є **Порівняти з оригіналом**,
**Історія** й **Повернути оригінал**. JS тут теж можна відкрити — але це вже свідоме порушення
обіцянки «не чіпаємо логіку», тож для підписів краще вкладка «Мітки».

### «Мітки»

Конструктор сканує HTML і рядки в коді та збирає видимі тексти (`placeholder`, `title`, `aria-label`,
текстові вузли, рядкові значення в JS) у один список із пошуком. У кожному рядку є файл, рядок і
колонка походження, а також дві кнопки: **«Правити текст»** створює правку в інспекторі (шукає елемент
за `id` з підказки, інакше — за текстом), **«До файлу»** відкриває файл-першоджерело на вкладці «Файли».

## Мережеві моки (вкладка «Мережа»)

Без даних панель показує свій стан «сервер недоступний» — це теж оформлюваний стан. Моків буває
два типи:

- **запит до сервера (URL)** — тіло JSON, яке поверне `fetch` (можна й справжній запит: без мока
  превʼю спробує сходити на адресу, з таймаутом 2,5 с);
- **повідомлення фоновіку (type)** — рівно те, що розширення отримає у колбеку
  `chrome.runtime.sendMessage`. Тобто для `background`-відповіді на кшталт
  `{ ok, status, data }` у полі тіла має бути весь цей об'єкт, а не лише `data`.

`match` — підстрока або регулярка (галочка), режим вибору поруч. Галочка `enabled` вимикає правило,
не видаляючи його.

## Живий перегляд

- Превʼю рендерить розширення у власній сесії через схему `extgui://`; CSP сторінок розширення
  знімається лише в цьому перегляді.
- Скрипти розширення працюють із заглушкою `chrome.*` (`resources/shim.js`): `runtime.getURL`,
  `sendMessage` (→ моки), `storage.*`, `tabs`, `i18n` та ін.
- Для контент-поверхонь є **Жива сторінка**: введи URL справжнього сайту — конструктор відкриє
  його й підключить скрипти/стилі розширення через `executeJavaScript`/`insertCSS`, щоб панель
  виглядала саме там.
- **Полото редагування показує лише інтерфейс розширення**: для контент-панелей це порожня
  клітинчаста область, а не макет сайту-господаря, тож мишкою не можна випадковохопити чужий
  елемент. Контекст реального сайту — тільки кнопка «Жива сторінка» (її `<body>` теж позначено
  як «господарський» і він не береться у здобич; `<body>` сторінки popup/options, навпаки, є
  самим інтерфейсом, тому лишається доступним).
- Ширина перегляду: вся / 360 px (popup) / 480 / 800 — зручно перевіряти адаптив.
- Прапорець **скін увімкнено** вимикає наш шар на час, щоб бачити «до/після».

## Структура даних

```
.projects/<id>/
  meta.json      ← назва, версія, звідки імпортовано
  original/      ← неторкнута копія розширення
  working/       ← копія, яку змінюємо
  skin.json      ← оформлення (операции + додатковий CSS поверхнями)
  history/<file> ← до 25 попередніх версій кожного файлу
  snapshots/     ← знімки всього проєкту
```

## Обмеження (варто знати)

- **MAIN world.** У превʼю всі скрипти контенту працюють в одному світі, тому розширення, що
  навмисно патчить `window`/`Storage` у головній світі (як-от ізоляція вкладок), поводиться інакше,
  ніж у Chrome. Конструктор попереджає про це у списку поверхонь.
- **.crx** розбирається простим зрізом за PK-заголовком; підписані Chromium-ом пакувальником
  екземпляри трапляються рідко, але перевіряй результат.
- **.xlsx / бінарні дані** не парсяться: якщо еталонка приходить із сервера, її треба емулювати
  моком.
- **Жива сторінка** не обходить жорсткий CSP у режимі `script-src` із nonce — тоді вставлений код
  може не запуститися; звичайне полото редагування (лише інтерфейс розширення) працює завжди.
- Перетягування мишкою змінює координати (`position` + `left`/`top`) і розмір, а не порядок вузлів
  у DOM. Справжня перебудова структури — це `appendTo`/`before`/`after` у `skin-runtime.js`:
  застосовувач їх підтримує, але в інтерфейсі конструктора окремого поля немає, тож таку правку
  дописують вручну в `skin.json` або роблять сирим CSS.
- Конструктор не підписує і не публікує розширення.

## Довідка по коду

| Файл | Призначення |
| --- | --- |
| `main.js` | вікно, схема `extgui://`, превʼю, IPC, автотест |
| `preload.js` | міст `window.gui` для інтерфейсу конструктора |
| `preview-preload.js` | ізолятор превʼю: пікер елементів, рух/розмір мишкою і стрілками, гарячий CSS |
| `lib/project.js` | імпорт/копіювання, історія, знімки, експорт |
| `lib/scan.js` | поверхні, мітки, попередження |
| `lib/skin.js` | схема скіна, генерація CSS, вставка/зняття шару |
| `resources/shim.js` | заглушка `chrome.*` і проксі `fetch` у превʼю |
| `resources/skin-runtime.js` | застосовувач шару, що їде в розширенні |
| `renderer/` | інтерфейс конструктора |
| `examples/demo-extension/` | навчальне розширення для автотесту |
